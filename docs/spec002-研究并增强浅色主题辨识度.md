# spec002：研究并增强浅色主题辨识度

> 状态：已修复、已部署并通过正式环境验收
> 日期：2026-08-17

## 1. 问题现象

“鸣潮 · 爱弥斯”切换到浅色外观后，界面文字仍可阅读，但主题辨识度明显下降：

- 主背景接近一整片白雾，场景细节和色彩被洗淡；
- 爱弥斯人物立绘只剩浅色轮廓，视觉焦点不明确；
- 青色轨道、极光、网格等主题装饰在白底上的存在感很弱；
- 与官方默认浅色界面的差异不够明显，难以一眼判断主题已经启用。

## 2. 实页研究

在正式 DSH Web GUI 的浅色模式下检查计算样式，发现三个提亮来源叠加：

1. 页面主层 `--dsw-alias-bg-base` 使用 `rgba(239, 248, 255, 0.64)`；
2. 背景左侧遮罩最高使用 `rgba(229, 247, 255, 0.88)`；
3. 场景色光使用 `mix-blend-mode: screen`，在浅色背景上只会继续提亮。

背景图本身又以高明度蓝白色为主，因此即使人物元素的 CSS `opacity` 为 `0.9`，最终合成画面仍缺少明暗和色相对比。问题不是文字颜色太浅，而是多个半透明层把主题内容共同推向了白色。

## 3. 设计原则

- 浅色主题仍保持明亮、通透，不改成伪深色主题；
- 通过降低大面积白色遮罩、增加冰蓝色玻璃层次来显露背景；
- 角色立绘使用适度饱和度、对比度和阴影增强，保留原画色彩；
- 浅色模式的极光改用 `multiply` 合成，轨道与网格使用更深的青、粉、金色；
- 菜单、弹窗和输入框仍保留较高不透明度，优先保证可读性；
- 深色主题变量和效果保持不变。

## 4. 实现方案

- 主页面基底透明度由 `0.64` 降至 `0.42`，侧栏由 `0.82` 降至 `0.72`；
- 背景图增加饱和度与对比度，并把近白遮罩替换为低透明冰蓝遮罩；
- 浅色场景光和极光单独采用 `multiply` 混合模式；
- 增强人物立绘、轨道环、网格、品牌文字和 composer 的青粉层次；
- 为浅色主基底透明度、浅色专用场景效果和背景对比度增加自动回归断言；
- 重新生成客户端 bundle、发布包与浅色预览图，并在正式环境验证。
